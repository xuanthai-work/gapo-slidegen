# Gapo SlideGen

Gapo SlideGen is a self-hosted internal web application for creating, editing,
presenting, and exporting AI-assisted presentations.

The repository is being rebuilt as a modular monorepo. The first implementation
milestone establishes a versioned slide contract and isolates the editor from
authentication, persistence, and AI providers.

## Current status

- Architecture, implementation plan, product specification, and initial design
  direction have been approved.
- The previous implementation is preserved in Git branch
  `archive/pre-rebuild-20260813`.
- The M0 editor boundary and schema-native PPTX export spikes have passed.
- PPTX export produces separately editable text, shapes, tables, charts, and
  uploaded images; a manual PowerPoint/LibreOffice fidelity pass remains.
- The FastAPI ingestion boundary handles prompt, manuscript, DOCX, PPTX, and
  text PDFs. PostgreSQL job models and the first Alembic migration are present.
- Internal email/password accounts use Argon2 and revocable opaque session
  cookies. Ingestion endpoints require authentication.
- Authenticated source endpoints persist normalized content and place uploaded
  files below owner-specific storage prefixes with compensating cleanup.
- The web shell includes login/register, a direct generation dashboard, recent
  presentations, and the editor boundary at `/editor`.
- Generation requests run through PostgreSQL jobs and a separate provider
  worker. The current local stub validates the full flow without external data
  transfer; the gateway adapter is pending its API contract.
- Persisted presentations use debounced autosave with owner filtering and
  optimistic revisions, so concurrent tabs cannot overwrite silently.
- Expired source inputs are removed by a bounded retention worker; active
  generation inputs are protected until their job finishes.
- The dashboard reopens owned presentations. The editor supports multi-slide
  navigation, keyboard present mode, and authenticated native PPTX downloads.
- Presentation titles can be edited from the dashboard or directly in the
  editor. Owned presentations can be deleted after confirmation; both actions
  use optimistic revisions so stale tabs cannot rename or delete newer work.
- Editor operations now cover slide add/remove/reorder, text and shape insert,
  text content and formatting, image fit and alt text, element deletion, and
  element duplication/layer ordering, and 100-step undo/redo with keyboard
  shortcuts.
- Source generation is a one-click flow that creates an internal structured
  story plan and opens the resulting presentation directly in the editor.
- Users can upload owned PNG, JPEG, and WebP assets up to 10 MB, place them on
  slides, see them in edit/present modes, and embed them in native PPTX exports.
- Generation offers three native-editable visual themes and rotates through
  multiple content layouts instead of emitting one repeated slide composition.
- The editor AI panel can rewrite either a selected text element or every text
  block on the current slide from a prompt. Whole-slide rewrites preserve
  element identities, layout, and styles, and apply as one undoable autosaved
  canonical operation.
- The same panel can generate a private 16:9 image from a prompt, add it to the
  current slide, or replace a selected image while preserving its editable
  frame. Generated bytes are validated and stored through the owned asset
  boundary before the editor receives an asset id.

## Commands

```bash
npm install
uv sync --project apps/api --python 3.12
npm run check
npm test
```

Run the local services independently:

```bash
npm run db:up
npm run db:migrate
npm run dev --workspace @gapo-slidegen/web
npm run api:dev
npm run worker:dev
npm run cleanup:dev
```

The local PostgreSQL credentials in `compose.yaml` and `.env.example` are for
development only. Docker Desktop must be running before `npm run db:up`.

## Temporary Google AI Studio provider

The local `stub` remains the default and never sends source content outside the
machine. To test outline quality with the Gemini Developer API, create a root
`.env` file (it is Git-ignored) and set:

```dotenv
SLIDEGEN_GENERATION_PROVIDER=google-ai-studio
SLIDEGEN_GOOGLE_API_KEY=your-google-ai-studio-key
SLIDEGEN_GOOGLE_MODEL=your-model-id
```

Image generation is configured independently, so the working text model does
not need to change:

```dotenv
SLIDEGEN_IMAGE_PROVIDER=google-ai-studio
SLIDEGEN_GOOGLE_IMAGE_MODEL=your-image-model-id
```

Do not put the key in `.env.example`, frontend variables, screenshots, or Git.
Restart both FastAPI and the generation worker after changing provider settings.
Then create a new source and generate the presentation from the dashboard.

With this provider enabled, normalized prompt/document text (up to
`SLIDEGEN_GOOGLE_MAX_INPUT_CHARS`, default 120,000 characters), the requested
language, title, and slide count are sent to Google. Gemini returns a structured
story plan; the local deterministic renderer converts it to native editable
slide elements without a second Gemini request. Uploaded image assets and the
resulting presentation document are not sent to Google in this flow. When a
user explicitly applies an AI rewrite in the editor, only the selected text or
the current slide's text blocks, plus the instruction and presentation
language, are sent to Google. Element geometry, styles, image assets, and the
rest of the presentation are not sent for an editor rewrite.

For explicit image generation, only the image prompt and requested aspect ratio
are sent to the configured image provider. The provider receives no source
document, slide text, geometry, existing image, or full presentation. Returned
PNG/JPEG/WebP bytes are limited to 10 MB, checked by magic bytes, and stored
under the authenticated user's asset prefix. Leaving
`SLIDEGEN_IMAGE_PROVIDER=disabled` keeps this feature unavailable without
affecting uploads, text generation, editing, or export.

Deleting a presentation removes its database record but intentionally does not
delete image assets immediately. Assets can be referenced by another deck or
by undo/history state; orphan-asset retention is handled as a separate cleanup
concern rather than risking broken presentations.

The application services and deployment configuration will be added through
vertical milestones after the M0 feasibility checks pass.
